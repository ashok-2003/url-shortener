# Backend (workstream C) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the foundation's stubs with the real backend: create, list and stats against D1, the redirect with
its KV cache, and the click pipeline from queue to D1. Then measure the `worker.ts` fast path and decide whether it
stays.

**Architecture:** The tRPC router calls the services in `src/server/links/`, which use Drizzle on D1.
`resolveRedirect()` reads KV, falls back to D1, answers, and sends one queue message after the response. The queue
consumer in `worker.ts` turns each batch into one D1 transaction that inserts events and updates counters, counting
each click once. Decision records are in `docs/decisions/`, the platform limits in `docs/architecture/scaling.md`, and
the diagrams in `docs/architecture/flows.md`.

**Tech Stack:** Next.js 16.4.5 on Workers via `@opennextjs/cloudflare` 1.20.16, tRPC 11.24, Zod 4.6, Drizzle 0.45.4
on D1, Workers KV, Cloudflare Queues, Vitest 4.1.12 with `@cloudflare/vitest-pool-workers`.

**Spec:** `docs/superpowers/specs/2026-11-06-url-shortener-design.md`, §5 to §8 and §11 to §13. Also read
`docs/superpowers/plans/2026-11-06-foundation.md` (the code this plan builds on; A and B's first phase are on `main`
as `94c7c76`) and
`docs/superpowers/specs/2026-11-06-testing-design.md` (the tests this plan makes pass).

## Review Focus

1. **`server-only` inside the Wrangler bundle.** `worker.ts` is bundled by Wrangler, not by Next.js, so
   `import "server-only"` resolves to the package's throwing `index.js`, and the Worker would crash on load. The fix is
   the Wrangler `alias` in Task 4 Step 7, and the check is Task 4 Step 9.
2. **KV failing or holding a malformed value.** The redirect must fall through to D1, never error. Tested in Task 5
   (`redirect-resilience.test.ts`).
3. **D1 failing on a KV miss.** The answer must be `503` with `Retry-After: 5`, not `404`, and must enqueue no click.
   Tested in Task 5.
4. **Non-ASCII or parser-rewritten targets.** `Location` must be ASCII. Store `new URL(url).href` and re-check the
   length afterwards. Tested in Task 2 (`create-normalize.test.ts`).
5. **A batch made only of redelivered clicks.** It must leave `clicks` and `last_click_at` untouched: not zeroed, not
   nulled. Tested in Task 4 (`record-redelivery.test.ts`).

- [ ] **Step 7: Implement `recordClicks`, the consumer, `worker.ts` and the Wrangler settings**

`recordClicks` runs one `db.batch()`. It has one insert per event and one update per distinct link, built with
Drizzle's query builders and `sql` fragments:

```sql
INSERT INTO click_events (id, link_id, clicked_at, referrer, country, device_type, browser, os, batch_id)
VALUES (?, ?, ?, ?, ?, ?, ?, ?, :batchId) ON CONFLICT(id) DO NOTHING;

UPDATE links
SET clicks = clicks + (SELECT count(*) FROM click_events WHERE batch_id = :batchId AND link_id = :linkId),
    last_click_at = max(coalesce(last_click_at, 0),
                        (SELECT max(clicked_at) FROM click_events WHERE batch_id = :batchId AND link_id = :linkId))
WHERE id = :linkId
  AND EXISTS (SELECT 1 FROM click_events WHERE batch_id = :batchId AND link_id = :linkId);
```

The `EXISTS` guard is what keeps a redeliveries-only batch from touching the row.

- **`handleClickBatch`:**
  - calls `readEnv(env)` first;
  - for each message where `isClickMessage` is false, logs `click.bad_message` and calls `message.retry()`, so after
    the retries it lands in `clicks-dlq` instead of being deleted (fail loud);
  - acks nothing explicitly, and maps the rest with `toClickEvent`, which uses `parseUserAgent` and renames
    `referrerHost` to `referrer`;
  - calls `recordClicks(getDb(env.DB), events)`.

  If that throws, log `click.record_failed` with the batch size, then rethrow: Queues retries the batch.
- **`worker.ts`:** `queue: (batch, env) => handleClickBatch(batch, env)`. Import with a relative path
  (`./src/server/clicks/consumer`), because Wrangler doesn't read `tsconfig` paths.
- **`wrangler.jsonc`:**
  - add `"max_concurrency": 2, "max_retries": 3` to the consumer;
  - add a top-level `"alias": { "server-only": "./node_modules/server-only/empty.js" }`. That's the same empty module
    Next.js uses on the server (Review Focus 1).
