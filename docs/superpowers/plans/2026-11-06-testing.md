# Contract Test Suite (workstream D) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A test suite, written from the spec, that tells us at any moment whether the shortener still keeps its
promises. It also comes with a speed report and five phone-sized E2E journeys.

**Architecture:** Vitest unit tests run in Node. Integration tests run in `workerd` through `@cloudflare/vitest-plugin`
against real D1, KV and Queue bindings. Playwright runs the E2E journeys against `pnpm preview`, and a plain Node
script produces the speed report. The tests go through public seams only (testing design §4). Tests for parts not
built yet are skipped with a `PENDING(X)` marker. Tests that need C's new modules, or that fail against built code,
go on a handoff branch for C instead of `main`.

**Tech Stack:** Vitest 4.1.12, `@cloudflare/vitest-plugin`, Playwright (`@playwright/test`), Drizzle 0.45.4, tRPC 11,
Node 22.

**Spec:** `docs/superpowers/specs/2026-11-06-testing-design.md` (the testing design) and
`docs/superpowers/specs/2026-11-06-url-shortener-design.md` (the product spec). Read both.

## Global Constraints

- **pnpm only.** Add each dependency at the newest version pnpm's release-age policy accepts. Never add
  `minimumReleaseAgeExclude`.
- **Vitest stays at 4.1.12.**
- **`@cloudflare/vitest-plugin`, not `@cloudflare/vitest-pool-workers`.** The old package is deprecated and renamed
  (npm notice on 0.23.0). It's the same integration under a new name, with the same `cloudflare:test` API. The
  product spec §12 still names the old package; tell the owner it changed.
- **Files D may edit:** `vitest.config.ts` (the `workers` project only), `package.json` (devDependencies and the
  scripts `test:e2e` and `bench`), `.gitignore`, `playwright.config.ts`, `tests/**` and `scripts/bench/**`.
- **Files D never edits:** anything under `src/`, `worker.ts`, `wrangler.jsonc`, A's tests (`tests/unit/*.test.ts`
  that already exist), and C's folders `tests/unit/server/` and `tests/integration/server/`.
- **No test-only switches in production code.** No real network: targets are `https://example.com/...` and are
  never fetched.
- **Files stay under 500 lines.** Import from `src` with `@/`.
- **Exact copy, from the spec and A's code:**
  - "Paste a link to shorten", "Enter a full link, starting with https://", "Use an https:// link".
  - "Links with a username or password aren't allowed", "Links can be at most 2048 characters".
  - "That's already a short link from this app".
  - "Pick a time at least 5 minutes from now", "Pick a date within a year", "Pick a valid date and time".
  - "Something went wrong on our side.", "This link doesn't exist.", "You've made 5 links in the last minute."
- **The PENDING marker** is one comment line directly above the skipped block, which is grep-able as `PENDING(`:
  ```ts
  // PENDING(C): real create/list/stats replace the stub fixtures
  describe.skip("links contract", () => { /* ... */ });
  ```
- **Commits:** `test: <what>`. No `Co-Authored-By` trailer (project `CLAUDE.md`).
- **Done means** `pnpm test`, `pnpm typecheck` and `pnpm lint` all pass. Report the output.

## Branches and parallel work

- **Task 1** (the harness) goes first and merges to `main` at once, because C is waiting on it.
- **After Task 1,** Tasks 2–10 touch disjoint files. Each may run in parallel in its own worktree branched from
  `main`.
- **Task 11** collects them:
  - Tasks 2, 4, 5, 7, 8, 9 and 10 go to `main`.
  - Tasks 3 and 6 go to the branch `test/handoff-c`, which C merges into its own work. They import modules C hasn't
    created yet, or they fail against built code (the owner chose "hold back").

## Review Focus

1. A slug path with a query string (`/abc1234?utm_source=x`) still redirects, but a trailing slash (`/abc1234/`)
   is a 404 that touches no storage. Tests are in Task 5.
2. A `cursor` that belongs to another owner's link returns only the caller's own older links, never the other
   owner's. Tests are in Task 7.
3. A whitespace-only URL (`"   "`) gives "Paste a link to shorten". Tests are in Task 2.
4. A custom expiry with an offset (`2026-11-06T17:35:00+05:30`, which is 12:05Z) is the same instant: accepted at
   exactly 5 minutes ahead. Tests are in Task 2.
5. Two creates of the same URL give two different slugs (spec §6: no hash of the URL). Tests are in Task 4.

      `settle()` awaits every promise passed to `waitUntil`.
    - `countingEnv(): { env: CloudflareEnv; touches(): number }`. It counts every property access on `DB`,
      `LINKS_CACHE` and `CLICKS`.
    - `capturingQueue(mode: "real" | "hang"): { env: CloudflareEnv; sent: unknown[] }`. `"real"` records each
      message and then forwards it to the real `CLICKS`. `"hang"` records it and returns a promise that never
      settles.

- [ ] **Step 2: Write the rules under `// PENDING(C): …` and `describe.skip`**

- **Basics:**
  - A link gives `302`, `Location` equals `targetUrl`, and `cache-control` is `private, no-store`. The status is
    never `301`.
  - `/abc1234?utm_source=x` gives `302`.
  - Slugs are case-sensitive: insert `AbC1234`; `/abc1234` gives 404 and `/AbC1234` gives 302.
  - An unknown 7-character slug gives 404, with a body containing "This link doesn't exist" and `no-store`.
- **Expiry and KV:**
  - On the frozen clock, `expiresAt = now` gives `410` and "This link has expired", while `now + 1 ms` gives 302.
  - **A KV entry that outlives its link:**
    - Create a link expiring at `now + 2 min`.
    - Request it, then `settle()`.
    - Advance the fake clock 3 minutes.
    - The next request gives 410.
  - **The KV fill**, on the real clock (KV expiry runs on Miniflare's clock):
    - After a first GET and `settle()`, `LINKS_CACHE.list({ prefix: "link:" })` has `link:<slug>`.
    - Its `expiration` is about now + 7 d for "never", now + 3600 s for a link expiring in 1 h, and now + 60 s for one
      expiring in 30 s, each within ±5 s.
  - **"Not found" is never cached:** GET an unknown slug S gives 404. Then `insertLink({ slug: S })`, and the next
    GET gives 302.
- **Clicks:**
  - `HEAD` gives 302 and `capturingQueue("real").sent` is empty. `GET` gives exactly 1 message:
    `{ clickId: <uuid>, linkId, clickedAt: <number within 1 s of now>, referrerHost, country, userAgent }`.
  - **No waiting:** with `capturingQueue("hang")`, `runRedirect` still resolves within 1000 ms. Use `Promise.race`
    with a timer.
  - **A real `send()` inside `waitUntil`:** with `capturingQueue("real")`, `settle()` resolves without throwing.
    Spec note: `docs/architecture/scaling.md` asks for this proof.
  - `cf: { country: "IN" }` gives `country: "IN"`. `cf: null` gives `country: null`.
- **Server-Timing:**
  - It matches `/kv;dur=[\d.]+/`, `/d1;dur=[\d.]+/` and `/total;dur=[\d.]+/`.
  - On the second (KV-hit) request it contains `d1;dur=0`.
- **Non-ASCII targets:** create `https://example.com/€` and `https://例え.jp/` through `callerFor`. GET each:
  `Location` equals `new URL(input).href` (`…/%E2%82%AC` and `https://xn--r8jz45g.jp/`), and the status is 302.
